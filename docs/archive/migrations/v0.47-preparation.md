## 三项可观察错误边界的决定

以下是迁移前发现的留白；已选项记录用户决定，未选项仍为建议。它们尚未写入 current Guide。

1. **非法 UTF-8 的偏移。** `41 E2 28 A1` 中，非法多字节序列从偏移 1 开始，
   不符合 continuation 要求的字节在偏移 2。原合同“首个非法字节”没有区分两者。
   用户于 2026-10-29 选择返回错误序列起点：此例为 1；截断的 `41 E2 82` 也为 1；孤立 continuation 报其自身偏移。
2. **数字解析的多重错误。** `9223372036854775808x` 同时超出 Long 且含非法字符。
   用户于 2026-10-29 选择语法错误优先：先验证完整词法形状，再检查数值范围，返回 `InvalidDigit(19)`；仅由合法数字组成的
   `9223372036854775808` 返回 `OutOfRange`；空串及只有正负号返回 `MissingDigits`。
   `"x"` 返回 `InvalidDigit(0)`；不采用顺序累积首次溢出后忽略非法后缀的规则。
3. **String 的 Int 长度上限。** 已批准 `byteLength(): Int`；Guide03 的 Int 是 32 位，
   [ADR-0018](../../adr/accepted/0018-string-owner-runtime-abi.md)及当前 concat helper 使用目标 `usize`，
   现有长度加法没有 2147483647 字节限制。需要明确超额输入、字面量及动态构造各自的失败方式，
   不能只在 byteLength 上截断／转换，也不能在规范迁移时宣称 runtime 已符合新上限。
   用户于 2026-10-29 选择以下映射和 nullable checkedPlus。保留 usize 内部布局，在创建边界执行 Int 上限：过大字面量为编译诊断，argv 为进入 main 前的
   operational failure，有显式输入上限的 IO 为 `LimitExceeded`，动态 `+` 沿用 Abort。
   Guide09 同时要求输入相关 Abort API 有可恢复版本；补 `String.checkedPlus(other: String): String?`，
   仅长度超限返回 null，成功返回新 owner，OOM 仍沿用分配 Abort。不另增 Result 连接或 LengthExceeded 分类。
   选定方案必须同样核对插值、Path.join、解码及其他创建入口，不能只给 `+` 加门。

- v0.46 已定义 Display、字符串插值、Result main；Guide13 旧 String 段落仍写“转换协议尚未封闭”，

  当前 CLI `process_entry_shape` 仍只接受 Unit 返回。迁移可以先完成，生产依赖须由实际实现闭合。
