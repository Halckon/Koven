# ADR-0035: 最终调试产物的发布与失败边界

> **性质**：架构决策记录 · **状态**：accepted · **读取时机**：实现 CLI 最终调试产物时 · **唯一真源**：本 ADR

## 状态

accepted

## 接受依据

用户于 2026-10-29 明确选择：默认 build 生成 dSYM；失败可保留并明确报告
已发布调试包，禁止删除他人产物。实施与双宿主验收由 SPEC-0366 维护，接受不代表实现。

## 决策

- 保持既有 CLI 参数形状。macOS 成功 build 交付 executable 与追加 `.dSYM` 后缀的匹配
  调试包；Linux 成功 build 保留最终 ELF 源码行调试信息。不新增 debug 开关或变量调试。
- single/project 共用本轮产物所有者。对象、链接和调试收集置于私有 staging，收集完成
  前保留对象。已有任一最终路径（含悬空 symlink）均拒绝，发布也必须 no-clobber。
- 调试包先发布、executable 最后发布，两者均就绪才成功。不宣称双路径构成原子事务。
- 调试包已发布而 executable 发布失败时，返回 operational error，明确报告遗留调试包
  路径；允许该部分产物保留，不递归删除可能被外部替换的公开目录。
- 私有 staging 仍清理，清理失败也明确报告。检查 inode 后再删除仍有替换竞态，不作安全
  回滚证明。外部并发创建/替换不得导致覆盖或删除他人产物，失败不得启动旧程序。
- run 保持其私有临时目录及进程生命周期。项目实际调试源码来源在 Spec 内封闭，不能借此
  修改诊断/源集合逻辑身份或让 codegen 猜测磁盘路径。

## 取舍与关联

接受默认 macOS 构建增加伴随物及调试工具前置，以明确失败报告替代不安全的公开目录回滚。
单目录包和新增 debug 参数均未选择。验收覆盖已有路径、工具/发布/清理失败、并发边界及
实际双宿主源码断点，不以对象行表或空 dSYM 代替最终产物成功。

局部扩展 [ADR-0010](0010-first-native-object-and-linker-contract.md) 的编排产物生命周期；
系统 driver、参数数组与 object emission 决定保持。
[ADR-0011](0011-first-dwarf-line-mapping.md) 的行表范围不变。
