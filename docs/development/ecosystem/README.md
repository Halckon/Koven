# Koven v1 生态开发路线图

> **性质**：跨仓库交付规划 · **状态**：approved（规划，不启用新语义） · **读取时机**：安排 v1 生态工作与联合验收时 · **唯一真源**：本目录的生态目标、依赖及联合验收

用户于 2026-10-22 要求落地此规划。当前切片建立治理文档；后续功能须满足语义、Spec 和依赖前置。
产品 v1 不等于 Guide 版本；本目录不改变 [现行 Guide](../../guide/README.md) 或已有 Spec 状态。

## 仓库分工

| 仓库 | 职责 | 边界 |
|---|---|---|
| [Koven](https://github.com/Halckon/koven) | 编译器、runtime、标准库、CLI、LSP、formatter、测试／文档／依赖工具、安装包、教程与验收示例、生态总规划 | 语言及示例真源；保留五个 workspace member，新增 crate 另走 ADR |
| [koven-site](https://github.com/koven-lang/koven-site) | 门户、教程／API 呈现、Playground 前端、练习及所有权／IR 展示 | 固定版本消费；不复制语言规则或执行任意源码 |
| [koven-editors](https://github.com/koven-lang/koven-editors) | VS Code、JetBrains 插件，工具链、语言服务、运行／测试／调试交互 | 消费编译器事实；不另建语义分析 |
| koven-playground（待建） | 在线执行 API、调度、沙箱、配额、分享存储与部署 | 到服务实施时建仓；使用固定工具链；不维护编译器分叉 |
| 官方扩展库（待建） | 可独立发布的 JSON、CSV、配置等库 | 本地／远程复用能力成熟且有真实消费者后再拆仓 |

标准库、三个示范程序、Kovenlings 首片源码与答案验证留主仓库。网站只呈现或消费生成内容。
Ownership Explorer 分为主仓库事实导出、网站呈现、IDE 适配。包管理客户端归主仓库；Registry 后置。
TextMate／Tree-sitter 原始资产保留主仓库真源，插件按锁定提交同步；消费副本不手工维护第二套规则。
不新增纯治理仓库，不预建空服务或库仓库。

## 优先级与里程碑

P0 优先形成实用预览；P1 补齐正式 v1 或扩大采用；P2 按需求触发，不阻塞 v1。
“可并行”不表示没有依赖；必需性与优先级分别记录。

| 顺序 | 里程碑 | 优先级 | 正式 v1 必需 | 依赖与退出目标 |
|---|---|---|---|---|
| 0 | [ECO-V1-M0 治理与接口基线](M0.md) | P0 | 是 | 建立归属、合同、版本和验收映射 |
| 1 | [ECO-V1-M1 实用预览](M1.md) | P0 | 是 | M0；安装后完成三个工具的构建、测试与运行 |
| 2 | [ECO-V1-M2 学习与试用](M2.md) | P1 | 否 | M0；与 M1 并行，按各子项真实能力启动 |
| 3 | [ECO-V1-M3 项目与库开发](M3.md) | P1 | 是 | M1；本地库复用、IDE 与基础调试闭环 |
| 4 | [ECO-V1-M4 正式发布](M4.md) | P1 | 是 | M1、M3；语言承诺与跨仓库版本组合验收 |

M2 未交付不得宣传在线运行。M4 对本次发布包含的网站／插件验收，不强制引入未完成的可选功能。
线程／Channel 保留正式 v1 承诺，允许首个预览延期；动态分发、Shareable、协程和自举不提前启用。

## 后续探索（按投入顺序）

| 顺序／优先级 | 方向与归属 | 启动条件与最小验收 |
|---|---|---|
| 1／P1 | Ownership Explorer：主仓库导出，网站／IDE 消费 | 已有事实稳定；move、借用和清理位置可追溯；未知显式标注，静态事实与运行事件分开 |
| 2／P2 | 远程依赖、锁文件和缓存：主仓库 | 本地依赖闭环；固定内容重建、离线缓存与篡改失败 |
| 3／P2 | 官方扩展库：独立发布仓库 | 核心 API 稳定且两个实际消费者；有版本、测试、文档 |
| 4／P2 | Compiler Explorer／成本看板：主仓库产出、网站呈现 | 可靠映射和基线；记录版本、目标、优化与测量环境，不用沙箱结果作性能排名 |
| 5／P2 | 单文件脚本：主仓库 | 真实自动化需求；先完善 run、缓存和进程交互；顶层语句另定语义 |
| 6／P2 | 公共 FFI、库产物及 API 兼容检查：主仓库／封装库 | 真实外部调用或版本升级需求；验证所有权、ABI、错误与清理，不开放未经批准的用户 unsafe |
| 7／P2 | Registry：独立服务 | 第三方发布需求；不可变版本、内容校验、撤回和归属闭环 |
| 8／P2 | 脚本宿主、REPL、Notebook、WASM | 明确应用需求；先定会话状态、重定义、move／borrow 和资源清理，不作为 Playground 前置 |

各项先形成候选里程碑再拆 Spec；本表不预占编号，也不授权新语义。
