# M5 度量与分发：Spec 起草材料

> **性质**：待编号 Spec 起草材料 · **状态**：draft / M5b候选包首片由0272承接 · **读取时机**：设计成本测量或双宿主 preview 交付时 · **唯一真源**：本页维护候选测量协议与交付验收；不记录未执行的性能或发布结论

## 1. Goal 与阶段

M5a Goal：在固定输入和环境下建立可复现的成本基线，能解释后续实现对成本的影响。
M5b Goal：让用户在声明支持的新环境安装 preview，运行固定多文件程序并理解能力限制。
主要涉及 Phase 6 工程交付及现有 native/runtime 边界；不新增语言语义。
共同启动/调整规则见[计划](post-governance-milestones.md)。起草时仅有文档授权；
后续持续实施授权已由 [0272 候选包合同](../archive/specs/0272-preview-candidate-package.md)
承接双宿主 release tar 与正常安装首片。其验收只在 Spec 维护，M5a、D06 安装负向、
签名/下载隔离等未选定范围仍为候选，不由该首片关闭。

两部分可拆成独立正式 Spec。preview 前置为 [M1A](multifile-program-spec-draft.md)和
发布合同选定的 [M4a](memory-safety-validation-spec-draft.md)门槛；
实用文本版本再依赖 [M1B](text-processing-spec-draft.md)。完整比较榜单和外审不是默认前置。
治理阶段的旧成本证据仍按原账本解释，新协议不能倒填或替代缺失的历史原值。

## 2. M5a：测量协议候选

| 维度 | 固定条件与输出 | 常见误判的排除方式 |
|---|---|---|
| 编译器自身构建 | 源码 SHA、lockfile、Rust/LLVM、profile、目标、依赖准备方式 | 与 Koven 用户程序编译成本分开 |
| 用户程序编译 | 固定源码集、相同语义与优化选项，分清前端、codegen、链接或端到端 | 不把改变工作量当作优化 |
| 冷/暖缓存 | 明确定义 Cargo target、增量、链接与文件缓存条件，分别保留原值 | 未控制 OS 缓存时如实命名，不称完全冷启动 |
| 时间与内存 | 每次 elapsed、适用的 CPU 时间、峰值 RSS 及单位/子进程口径 | 不直接混用不同宿主工具的数值 |
| 产物与运行 | 可执行文件及依赖的尺寸、固定输入输出、运行时间和必要分配指标 | 去符号/动态依赖变化单独解释 |
| 对比与噪声 | before/after SHA、重复次数、样本顺序、机器负载、原始日志和摘要 | 不静默丢弃异常值，不由单次样本推出普遍结论 |

先跑小样本确定预算，再冻结正式采样协议和回归调查阈值。
阈值是调查条件，不能直接当作已达到的性能承诺；未获得数据前不填写提升百分比。
使用独立测量目录，不清理他人 target；避免并发争用同一 Cargo target 或测量宿主。
现有度量脚本能承接时复用，仅补缺失字段；报告保留原始日志位置、输入/产物摘要和失败样本。

Rust/C 对照属于可选后继。先验证相同输入、算法、结果、错误行为、工作量与资源责任；
若实现能力或运行模型不同，说明不可比部分，不做全面性能排名。

## 3. M5b：preview 交付合同候选

首轮目标沿用当前规划的 macOS arm64 与 Linux x86_64 glibc。
具体最低 OS/glibc、工具链版本、CPU 要求及安装依赖在实际构建环境核实后冻结；
本页不承诺任意 macOS/Linux 均可运行，也不新增 Windows、musl 或交叉编译支持。

| 决策 | 实施前必须确认 |
|---|---|
| 分发内容 | 编译器、所需 runtime/标准库、示例和许可材料的边界；不默认发布 Cargo workspace crates |
| LLVM/链接依赖 | 产物实际动态依赖、加载路径、链接器与 SDK 要求；选择外部安装还是随包交付并说明理由 |
| 打包与来源 | 版本、源码 SHA、构建命令、目标、依赖清单、校验和及归档内容 |
| 安装与移除 | 解压后的入口、PATH 或绝对路径用法、工作目录、用户可移除的文件范围 |
| 宿主信任机制 | 实测签名/隔离属性等对安装运行的影响；选择处理方式，不要求用户无说明地关闭系统防护 |
| 示例与限制 | 复用已验收程序，准确列出未支持 API/语法、平台、错误和检测覆盖 |
| 发布与回退 | 候选产物检查、版本标识和撤回/替换流程；外部上传、tag、release 按当次授权执行 |

公开文档指向现行 Guide 和已验收范围，不能把本批 draft 能力列为 preview 功能。
标准库公共逻辑与受控 native 桥接按当前架构交付；不依赖开发者机器上未声明的源码路径。
依赖、捆绑许可和分发条件按实际产物检查，不能仅凭 workspace 的许可字段推定全部合规。

## 4. 验收矩阵

| ID | 验收 | 证据 |
|---|---|---|
| D01 | 测量协议可重复执行，原始样本可追溯 | 固定输入、环境、日志和摘要；失败/噪声不省略 |
| D02 | before/after 工作量一致，比较结论有数据支持 | 正确性检查、样本分布、差异及不确定性 |
| D03 | 两个声明宿主从干净安装状态运行 | 无开发 checkout 依赖的构建/运行记录、实际动态依赖 |
| D04 | 包路径含空格/非 ASCII 时仍可用，移除不影响无关文件 | 隔离目录中的安装、运行、移除记录 |
| D05 | 固定项目的空参数、多参数、非 ASCII 输入输出一致 | 同一 M1A oracle、退出码和 stderr；实用版追加 M1B |
| D06 | 必需 M4a 门槛实际通过，缺失依赖有可操作错误 | 检测报告及安装负向场景 |
| D07 | 版本、源码、依赖、校验和与文档匹配 | 产物清单和发布前审阅记录 |

“干净安装”环境及预装工具列表需要记录。当前环境试跑不能替代两宿主新环境证据。
首次 preview 可以明确是手工安装，但用户路径必须可复现；自动更新、包管理器上架另列范围。

## 5. 非目标、可调整项与记录

首片不包含自动更新服务、全平台安装器、性能冠军目标或未经授权的公开发布。
样本集、测量工具、包格式和安装方式可随实际工具链调整，保留协议版本和不可比边界。
若依赖交付方式需要长期架构变化，补 ADR；不能用打包工作绕过语言或平台支持前置。

D01–D07、成本数值、兼容性、安装与发布均未执行；本轮不下载依赖或安装系统工具。
文档验证统一见[计划 §11](post-governance-milestones.md#11-文档起草记录)。
