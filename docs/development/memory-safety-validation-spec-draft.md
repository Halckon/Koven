# M4 安全验证：Spec 起草材料

> **性质**：待编号 Spec 起草材料 · **状态**：draft / M4a由0266承接，M4b首片由0269承接 · **读取时机**：准备为已支持的语言切片建立运行时安全证据时 · **唯一真源**：本页维护候选覆盖与验收；不宣称内存安全已获证明

## 1. Goal 与阶段

Goal：让实际生成代码中的选定内存错误能被检测、复现、缩小并转成回归测试，
区分检查器、lowering、runtime、检测接线和测试 oracle 的责任。
覆盖 Phase 2–5 产物与 Phase 6 验证设施，不新增语言语义。
共同启动/调整规则见[计划](post-governance-milestones.md)。用户持续实施与满足前置的
并行授权已由[0266](../archive/specs/0266-native-sanitizer-wiring.md)承接 M4a Linux 首片；
[0269](../specs/active/0269-generated-resource-programs.md)随后承接 M4b 的有限资源程序首片；
其正式合同与验收只在 Spec 维护，本页其余范围和 M4c 仍为候选。

M4a 可从 [M1A](multifile-program-spec-draft.md)起按切片接入；M4b 扩展随机执行；
M4c 为有明确范围的外审准备材料。三个子阶段各自验收，不要求先完成所有集合或线程功能。
检测平台、LLVM/runtime 能力和预算必须在实施基线实测，当前不承诺所有检测器均可用。

## 2. M4a：先证明检测接线生效

正式0266承接 Linux x86_64 固定 native 地址/泄漏检测子集及具体限制；其合同与结果只见正式 Spec。
后续覆盖扩展先盘点现有资源计数、错误注入、
变异测试及 CI 工具链，再选择最少的新设施，不另造一套编译流水线。

| 层次 | 必须记录的证据 | 不能替代的证据 |
|---|---|---|
| 生成的用户函数 | 实际编译/链接参数、产物、故意越界或失效访问探针的检测结果 | 只给 Rust 测试宿主加检测选项 |
| runtime 与 drop glue | 对实际参与执行的实现插桩；若有预编译部分，记录构建来源与覆盖缺口 | 仅有链接到检测库的日志 |
| ASan | 选定地址错误探针及干净对照，非零退出和预期报告类别 | 用一次触发概括全部内存错误 |
| UBSan | 工具链实际支持的选定操作、故意错误探针和报告 | 假定所有 LLVM IR 语义都可被自动检测 |
| 泄漏检测 | 独立启用方式、适用平台、正常无环场景与故意泄漏探针 | 将 ASan 运行成功写成已完成泄漏检查 |

探针属于隔离的测试设施，不作为正常 Koven 程序绕过前端检查的公开能力。
每个探针有稳定的错误类别预期；日志中的机器地址不进入 golden。
测试还应证明关闭相应接线时不会错误地报告“已检测”，防止把普通进程失败当成检测成功。
工具不支持的项标为未覆盖，并选择替代证据或明确阻塞对应发布门槛，不能成功跳过。

## 3. M4b：有界、可复现的程序生成

0269选定两个固定资源程序形状，当前实施中、尚未验收；以下未被选定的范围仍为候选。

生成器只覆盖已批准且实际支持的语义片；有效程序与故意非法程序分开生成和判断。
初始候选为顺序控制流、MoveOnly owner、字段替换、容器迭代与提前退出，
后续随 Map、闭包、线程的正式交付扩展；不把尚未支持的程序拒绝当作编译器故障。

- 有效程序：独立参考模型给出输出、owner 身份和必要资源事件；同时运行检测器。
- 非法程序：按批准规则预期拒绝类别及关键 Span，不因任意报错就算成功。
- 差分：只比较语义未变、两版共同支持的输入；旧二进制是辅助证据，不是唯一 oracle。
- 可复现：保留 seed、原始源码、编译器 SHA、工具链、flags、平台、命令、输出及退出状态。
- 最小化：缩小器保持触发性质和必要前置；保留原始失败及最小失败，单独确认不是超时变化。
- 预算：限制源码大小、执行时间、内存、子进程和生成总量；超时/资源耗尽单独分类。

不要使用被测 ownership/drop 计划生成全部预期，否则相同遗漏会同时污染实现和 oracle。
运行目录与失败产物隔离；清理只删除本次创建的临时产物，保留失败所需资料。

## 4. 资源语义与失败归因

正常无环路径验证每个 owner 的唯一释放、次序及仍存活的 loan；内容正确不能代替资源正确。
现行 Rc 强环允许无法释放、Abort 不展开，分别按
[runtime 规范](../guide/13-program-runtime-standard-library.md)和
[所有权规范](../guide/10-ownership-borrowing-drop.md)分类。
这不是统一抑制泄漏或 UAF 报告的理由：每条豁免必须能定位到对应语义和具体样例。

失败先保全证据，再判断属于类型/所有权事实、SSA 交接/验证、runtime、检测设施或预期模型。
修复需加入能在修复前失败的回归；不能只减少随机样本或把失败 seed 加入排除表。
并发相关检测在 M6 合同确定后单独选择，ASan 通过不代表没有数据竞争。

## 5. 验收矩阵与外审交付

| ID | 验收 | 必备产物 |
|---|---|---|
| S01 | 各选定检测层的故意错误能触发，干净对照通过 | 工具版本、插桩范围、真实命令与报告 |
| S02 | 固定程序输出和资源事件符合批准合同 | 独立 oracle、双宿主功能结果与检测宿主结果分别记录 |
| S03 | 有效/非法生成器各自能捕获已知注入缺陷 | 可复现 seed、源码、类别与误报处理 |
| S04 | 同 seed 可复现，失败缩小后仍保持原因 | 原始/最小输入、重放命令、环境 |
| S05 | 差分、Abort、Rc 环和预算退出不混淆 | 支持交集与分类样例 |
| S06 | CI 接线失败、检测器缺失或必需任务跳过会显式失败 | 负向门禁证据及成本预算 |
| S07 | M4c 外审范围和材料可重放，意见有处置 | 指定 SHA、假设/威胁边界、复现包、发现与修复状态 |

首次 preview 只要求正式发布合同选定的 M4a 子集实际通过；未选择项明确列为限制。
M4b 样本数量、M4c 外审都不能作为完整内存安全证明，也不自动成为首次 preview 的无限前置。
外审材料可以本地准备；邀请审计者、发送源码/报告或披露问题需对应授权。

## 6. 非目标、可调整项与记录

首片不同时实现完整 fuzz 平台、全部平台 sanitizer、模型检查器或安全认证。
检测器组合、语义片、预算和 CI 频率可按实际能力调整；必须保留覆盖变化及风险依据。
正式 Spec 分别承接 M4a/M4b/M4c 的可独立验收范围，不预占编号。

S01/S02/S06的选定首片结果只见0266，尚不等于各项完整通过；S03–S05/S07与外审未执行。
文档验证统一见[计划 §11](post-governance-milestones.md#11-文档起草记录)。
