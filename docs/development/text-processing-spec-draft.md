# M1B 文本处理工具：Spec 起草材料

> **性质**：待编号 Spec 起草材料 · **状态**：draft / M1B-a现行语义首片由0274承接 · **读取时机**：评审首个文本程序及其最小依赖时 · **唯一真源**：本页维护 M1B 候选需求；现行语义见 Guide

## 1. Goal、依赖与权限

Goal：一个多文件词频工具能够在两个受支持宿主处理固定输入，按确定的次序输出词与计数，
在正常结束及选定错误路径上正确处理资源。
所属 Phase 为 2–5 的语言/库能力及 Phase 6 的程序交付；具体 API 尚未获本稿启用。
共同起草、调整与启动规则见[里程碑计划](post-governance-milestones.md)的 G0–G3 和 §10。

前置为[M1A](multifile-program-spec-draft.md)、实际需要的[M3A](sequential-collections-spec-draft.md)
能力和新增文本/错误 API 的语义决定。M2、Map、Str、通用格式化均不是首版的当然前置。
用户允许实施时根据实际情况调整本稿；[SPEC-0274](../archive/specs/0274-argv-word-frequency.md)承接仅argv的首片。
普通应用decimal与重扫argv保持现行语义；本页不复制其合同/验收。文本输入b及新增API仍待各自前置。

## 2. 两个可独立验收的交付候选

| 切片 | 用户能力 | 实施前必须明确 |
|---|---|---|
| M1B-a argv 词频 | 将每个参数视为一个词，统计重复，输出词和十进制计数 | 特殊参数的展示、计数边界、整数文本转换、计数存储策略 |
| M1B-b 文本输入 | 从一种选定输入源读取文本并分词，复用统计逻辑 | stdin 或文件、UTF-8、分词/空白、大小限制、IO 错误、资源关闭 |

建议先实现 a，b 在其语义与底层接口具备后进入独立 Spec；不要求一次补齐两种输入源。
首次输出建议按词首次出现的顺序，避免依赖未定义的哈希遍历次序。以下只是便于评审的应用
输出候选，启用前必须在合同中定稿；不构成新的 String 或集合语言规则。

| argv | 候选 stdout（`\t` 为制表符，`\n` 为换行） |
|---|---|
| 无参数 | 空 |
| `apple` | `apple\t1\n` |
| `apple`、`pear`、`apple` | `apple\t2\npear\t1\n` |
| `猫`、`狗`、`猫` | `猫\t2\n狗\t1\n` |

成功候选为 exit 0、stderr 空。一个空字符串参数、含 tab/LF 的参数、文本内 U+0000、
非法输入字节和超过计数/容量上限各有独立决策项；不能只通过上表就声称程序合同完整。
输入时 String 必须继续满足现行 UTF-8 不变量，不能静默替换非法字节。

## 3. 前置决策与实现边界

| 决策 | 要回答的问题 | 完成证据 |
|---|---|---|
| T1 文本和输出 | 首次版本是否仅处理 argv；特殊词转义或拒绝；计数用哪一整数类型及转换函数 | 全输入域的应用规则与完整输出/错误表 |
| T2 存储 | 现行数组能否满足 argv 有界计数；若需 MutableList，究竟缺哪几个操作 | 端到端方案及具体 API 依赖；不以 Map 作为便捷但未批准的前提 |
| T3 错误与退出 | 哪些错误用 Result、哪些属于宿主 operational failure、哪些沿用 Abort；如何影响进程退出 | 与现行 Unit entry 和 CLI 边界一致的规则；若扩张则先启用规范 |
| T4 文本输入 | 输入源、UTF-8/换行/分词、长度限制、文件/流 owner、短读/读取失败 | 已启用 API 合同、目标 ABI 决策与正反输入 |
| T5 标准库边界 | 哪部分用 Koven 源码，哪部分属于最小 runtime 桥接；底层能力是否真正可用 | 公开入口、权限与 ABI 审计；不以 Rust shim 替代目标语言公共库逻辑 |

[String/IO/entry 规范](../guide/13-program-runtime-standard-library.md)只封闭当前最小 String 表面，
length、索引、slice、分词、整数转换或格式化不能由现有 concat/clone 推导。
新增表面转到 proposal，必要的 Guide 增量经明确启用后才能实施；本稿不确定新 API 拼写。
当前 `error()` 不保证 stderr 文本；不能把应用精确错误协议直接委托给它。

已有 Result 声明见[prelude](../../crates/lang-std/koven/prelude.ko)；构造/匹配、泛型具体布局、
后缀 `?` 的 typed/ownership/native 需要分别核验。当前
[unit lower](../../crates/lang-codegen/src/ssa/unit_lower.rs)中的通用拒绝边界不是 `?` 已支持的证据。
已有 generic/closure 能力只补具体实例缺口，保留 borrowed 与 move closure 的不同规则。

## 4. 验收与红测安排

| ID | 验收项 | 证据要求 |
|---|---|---|
| T-A | 应用基本行为 | 表中输入及定稿的特殊输入，真实 project build、artifact、run 全输出，双宿主 |
| T-B | 计数与容量 | 重复/不同词、容量边界、整数上界、增长前后旧词不变；有独立参考计数结果 |
| T-C | 文本来源 | b 才要求；空/多行/UTF-8/非法字节/读取失败/限制超额，按定稿协议核诊断与退出 |
| T-D | 错误清理 | 按 T3 选定的错误模型验证 owner 清理和成功后续执行；采用 Result 时覆盖 Ok/Err，采用 `?` 时另覆盖其提前返回，不强制同时交付 |
| T-E | 资源 | 字符串、计数条目、容器及选定 IO 资源分别核验；Abort 与正常释放分开 |
| T-F | 库与阶段交接 | 公共 `.ko` 入口、同名用户声明、能力/来源身份、错误 Span 与拒绝路径 |
| T-G | 回归和交付 | 受影响前端及 codegen/CLI 消费者，M1A 仍通过；在正式 Spec 记录准确选择与未运行项 |

先固定 T1–T5，再用最小复现确定缺哪一阶段；不通过改应用绕过已选验收项。
应用输出参考可用独立算法离线计算，但发布产物必须运行 Koven 程序，不能调用宿主实现替代。
M1B-a 与 b 分别记录退出条件，不以 a 通过宣称文本 IO 已交付。

## 5. 非目标、调整与当前记录

不默认加入 Unicode normalization、locale/case folding、正则、流式异步 IO、Map、Str、
通用 toString、借用返回、公开 C FFI 或全部标准库底层能力。
若简单有界 argv 版本无需动态容器，可删除其 M3A 依赖；若当前基线已补某 API，复用对应证据。
范围调整须同步应用合同和依赖，不能删除已选失败案例来获得绿灯。

| 项目 | 状态 |
|---|---|

| T-A–T-G、候选输出、性能与资源实测 | 未运行；等待治理交接及正式合同 |
