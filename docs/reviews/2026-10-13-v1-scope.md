## 0. v1 的定义

**v1 是一门能写真实命令行工具的语言，而不是一门能自举的语言。**

| 维度 | v1 承诺 | v1 不承诺 |
|---|---|---|
| 程序类型 | 单进程、同步 IO 的命令行工具和库代码：文本处理、数据转换、小型解释器、编解码器 | 并发服务、GUI、嵌入式 freestanding |
| 安全 | 被接受的程序内存安全、资源确定性释放；越界、溢出、`!!` 失败一律 abort 并打印消息 | 完整形式化证明；外部审计 |
| 编译器行为 | 合法程序要么正确运行，要么得到明确的"未实现"诊断；**不出现 ICE 或后端拒绝作为常态** | 性能对标 C/Rust；增量编译 |
| 平台 | AArch64 macOS、x86_64 Linux glibc | Windows、musl、交叉编译 |
| 生态 | 单 project、无依赖；`kovenc build/run/check/format`；LSP | 包管理、ABI 稳定、FFI |

**出口判据**（全部满足才发布 v1.0）：

1. 审计文档 §1 的六个验收程序（A 词频、B 配置解析、C 表达式求值、D RAII 状态机、E 二进制编解码、F 链表/栈）以 Koven 源码写出，在两个宿主上 build/run 输出正确，ASan/LSan 干净。
2. Conformance 矩阵（从 review 文档的 85 个 probe 扩展而来，按 Guide 每一章至少覆盖正反例）：合法程序 100% 运行，非法程序 100% 前端诊断，0 个 ICE。
3. 只有一条编译管线（单文件 = 一个文件的 compilation unit）。
4. Guide 不再含"当前实现到哪一步"的句子；实现进度由覆盖矩阵表达。

## 1. 必做：语言规则（Guide 增量）

这些是 v0.43 没有定义、或定义有误、但 v1 程序必需的规则。每项都应先进 Guide，再实现。状态列：❌ 未定义，◐ 部分定义。

| L2 | 字符串插值降级 | ◐（有语法，禁止降级） | `"${x}"` 要求 `x : Display`，降级为 builder 拼接 | L1 |

| L13 | Map 迭代 | ❌ | 借用式 provider，顺序固定为插入顺序 | 现有 List provider |
| L14 | 移出 v1 的内容 | — | 13 的 unsafe/extern/RawPtr 节、线程/channel 节、预声明 API 表中的线程项移到 proposals | — |

## 2. 必做：实现与工程

### 2.2 现有 Guide 能力的原生补齐

| 领域 | 待补齐 |

## 3. 建议做（v1.0 可选，做了明显更好）

| # | 内容 | 理由 | 不做的代价 |
|---|---|---|---|
| S1 | 非逃逸闭包以 exclusive loan 可变捕获 `var` | `each(xs) { sum += it }` 是最常见的回调写法；只扩 capture 模式，不引入 FnMut 层级 | 回调式 API 基本不可用，所有访问都得走借用返回 |
| S2 | 泛型推导读取 lambda 返回值（两段式） | 否则 `map`/`fold` 每次都要写全类型实参 | 不提供 `map`/`fold`/`filter` |
| S3 | owned 集合算法：`map`/`filter`/`fold`/`sort`/`contains`/`indexOf`/`reverse` | 返回新 List，不引入视图 | 用户手写循环 |
| S4 | 无后缀整数字面量在二元运算/比较中随对侧整数类型定型 | 没有隐式转换时，`b == 3`（`b: Byte`）现在报错 | 小宽度整数写起来很别扭 |
| S5 | `while`/`for` 循环标签 | 嵌套循环跳出 | 用标志变量 |
| S6 | Map 带初值构造（0291 草案） | `mapOf("a" to 1)` | 用 `mutableMapOf` + `put` |
| S7 | 只读 `borrow var` 游标（同根 shared 投影重绑定） | 链表/树的迭代遍历（审计 §2.11） | 只能递归遍历 |

## 4. 延后

### 4.1 v1.x（v1.0 之后、不改动内核）

| 内容 | 现状 | 延后理由 |
|---|---|---|
| 线程：`thread`/`join`/`channel`、`Transferable` 运行时检查（M6） | Guide 有规则，零实现 | 不影响单进程工具；规则可以先保留在 proposals |
| macOS 动态检测、UBSan、外部审计（M4 其余） | 未做 | v1.0 以 Linux ASan/LSan 为门槛 |
| 性能基线与正式分发（M5 其余） | 首片完成 | v1.0 不做性能承诺 |
| N1b、`filter` 视图、`consume` 链 | 草案 | 依赖 v2 的统一非逃逸模型（审计 §5） |
| `Weak<T>`、Rc 环处理 | 未定义 | 无共享可变时环很少见 |
| `Copyable` 显式 opt-in/opt-out | 未采纳 | 没有 `RawPtr` 前风险低 |
| `step`/`downTo`、反向迭代 | 未定义 | L4 落地后的增量 |

### 4.2 v2（需要新的内核概念）

| 内容 | 需要的前置 |
|---|---|
| `dyn`/interface 值、匿名对象 | 动态分发 ABI、对象身份、逃逸规则 |
| 统一非逃逸类型（合并借用结果、`View` carrier、借用闭包、迭代器） | Escapable 一类的能力设计 |
| 可存储借用、条件借用、多来源借用、`inout` 返回 | 同上 |
| 用户自定义索引与迭代协议 | 同上 |
| `Str`/`StringView`、零拷贝切片、`arr[a..<b]` | 同上 |
| `Shareable`、`Arc`/`Mutex`/原子、scoped threads | 线程转移（v1.x）之后 |
| `unsafe`、`RawPtr`、`extern "C"`、标准库用 Koven 自写 | unsafe 特权模型、C 布局、`USize` |
| 泛型多 bound、`where`、associated type、扩展函数与追溯式 conformance | 抽象机制整体设计 |
| `Array<T, N>`、const 泛型 | const 求值扩展 |
| 默认参数、`vararg`、data class/derive 语法 | 语法糖，按需求评估 |
| `T?` 与 `Option` 统一 | 现有 nullable 实现已大量投入，收益不足以在 v1 推翻 |

### 4.3 v3 及以后

协程/async、自举。保持现有 Guide 结论。

## 5. 现在应停止或冻结的工作

1. **N1a 范围 carrier 扩展**：冻结在已交付的 `take`/`drop`/`dropLast`，不启动 N1b、filter、更多范围算法。
2. **Map 新访问形态**：不再新增类似 `withValue` 的回调接口；主路径为 `get`/`requireValue`/迭代。
3. **单文件管线上的新能力**：E2 之前新能力只在 compilation-unit 管线实现。（10-14 状态：未遵循，0311–0314、0316 均为 single-only。）
4. **为单个"控制流 × 类型"组合开 Spec**：E3 之前积压这类需求，E3 之后用矩阵整体回归。（10-14 状态：未遵循，本区间 8 个 Spec 中 7 个属于此类。）
5. **为实现进度修改 Guide**：Guide 只在语义变化时改版。
6. **M2B 新组合切片**：PR #95 收尾清单完成后宣布 M2B 冻结，不再开新的 M2B 组合 Spec（10-14 新增）。

      └─> P2 补齐现有 Guide 能力（§2.2，以矩阵为单位推进）
