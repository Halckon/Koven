## 3. 新问题

### 3.1 Map `for` 被报成"语言非法"

```kotlin
fun main(): Unit { var m = mutableMapOf<String, Int>(); m.put("b", 2); m.put("a", 1); for ((k, v) in m) { println(k) } }
```

v0.44 的 Guide 12 明确启用了 `for ((key, value) in map)`，但两种模式都报 L0159"for source requires a compiler-bound sequential container, View, IntRange or LongRange"。
L0159 的含义是"这个来源在语言上不能迭代"。Guide 已经允许，实现尚未交付，按 0319 建立的分工应报 L0165（"尚未完成"），否则用户会以为自己写错了。0331 暂停期间，建议先把这条诊断改正。

### 3.2 待决设计点（非实现偏差）：语句位置的 `if/else` 与 `when`

这一差异是 Guide 06 的明文规定，实现与规范一致，不能当作缺陷修复。Guide 06 新规则："statement when 与无 else 的 if 保持 Unit；有 else 的 if 仍要求分支 join"。实测：

- `if (c) { 1 } else { "s" }` 写在语句位置：前端 L0089 拒绝（v04）。
- `when (c) { 1 -> 1; else -> "s" }` 写在语句位置：前端接受（v19；后端因 `when (Int)` 另有缺口而失败）。

两种写法的值都被丢弃，却一个要求 join、一个不要求。实际影响在 `if (c) xs.removeAt(0) else xs.add(1)` 这类分支返回不同类型、结果被丢弃的写法上，Kotlin 用户会经常碰到。
若要统一（要么语句位置的 `if/else` 也不求 join，要么语句位置的 `when` 也要求 join），需要作为语言规则变更单独确认，并补齐取代条文、诊断与成对验收；在确认之前维持现行规定。若决定保留差异，建议在 Guide 06 写明理由。

### 3.3 Guide 走在实现前面

Map 借用遍历已在 v0.44 Guide 中启用，0331 暂停，当前没有可运行路径。v0.44 的启用边界（Guide 15）写了"版本启用不等于全部实现"，形式上没有问题。
但这是 v0.44 唯一一项写进 Guide 却完全没有原生实现的能力，加上 §3.1 的错误诊断，用户无法分辨"写错了"与"还没做"。建议在 Architecture 的覆盖矩阵或教程里明确标注，并尽快恢复 0331。

### 3.4 README 与教程没有反映新能力

README/README_CN 已更新为"Guide v0.44"，但"当前原生子集"那句话仍只列了顺序集合、Map 查询、借用返回和范围借用，没有提 Range/`for`、整数转换、`consume`；教程也没有对应示例。
这次是文档落后于实现，和 10-13 时文档夸大实现正好相反，修起来很便宜。
