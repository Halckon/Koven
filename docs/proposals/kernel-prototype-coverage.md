## 2. 排期的原则

未覆盖项分两类处理（2026-11-15）：

- **会改变内核形状的，先做。** 判据是：答案不同，规则或基底的划分就要变。它们拖得越晚，建立在其上的原型返工越多。
- **只是扩大覆盖面的，记账后集中做。** 判据是：按现有规则推得出答案，只缺用例来确认。它们放到全部基底都有原型之后，用一轮专门的覆盖来清，届时也是把几个原型合并、统一活性分析的时机。

## 3. 先做的（会改变内核形状）

| 项 | 为什么会改变形状 | 归属 |
|---|---|---|
| 内部可变标记与借用规则、`Shareable` 的配合 | “共享借用即不可变”是 K1 的前提；例外怎样进入规则未检验 | KB6 |
| 挂起点两侧的借用状态守恒、帧内自引用 | 决定 loan 能否跨挂起点、帧是否必须地址稳定 | KB8 |
| 闭包捕获 | 之一把闭包定为“匿名的、含借用字段的积类型”；若成立则借用与能力两个原型都不需要新规则，若不成立则是一条新基底 | KB3、KB5 |
| 经借用把来源写进视图字段 | 现在只能拒绝（K14）；放开需要把流向子句推广到具体类型的字段 | KB3 |
| `deinit` 函数体：`this` 的访问方式、析构中再次失败 | 之四建议把 `this` 从只读借用放宽为可部分移出，直接改 KB1 的规则 | KB1 |

## 4. 记账后集中做的（扩大覆盖面）

| 项 | 归属 |
|---|---|
| 递归的视图类型；两阶段借用；语句级之下的活性精度 | 借用 |

| `Rc` 与 `Weak` 的析构义务 | 析构、能力 |
| 实现的四值判定里的“未知”与“错误”；interface 上界；可推导也可声明的能力 | 能力 |
| 逐条对照 Guide 10、11；移植 `Copyable`、`Transferable` 的实现测试 | 能力 |

## 5. 永远在欠账里的

- 健全性证明。每个原型只说明规则在它的用例上给出了预期结果。
- 原型的状态、事件与用例是作者选的；没有想到的情形不会被发现。至今原型自己的漏洞都是靠新增用例或对照测试发现的。
