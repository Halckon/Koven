与布局改造完全无关。D 不依赖 C 的 nullable while 收窄，consume 不依赖遍历 API。

## 3. 冻结前必须回答的细则

### A–C：完成类型事实，不放松阶段边界

现 Guide03 的基础 assignment deferred 与 Guide06 的 when→Any 规则需明确逐段取代；
仅统一诊断文字不能替代语义决定。始终保持完整类型准入在 ownership 之前，不为显示旧错误码
绕过 final admission，也不把任意 Error/Deferred 当作成功。单文件 B 需对齐 unit 的声明类型
检查，但不顺带扩大 unit 已有字段赋值到本片。结果 Unit 仍可处于兼容的值上下文，例如
Unit 期望的初始化或 lambda 尾表达式，不收窄为“只能作语句”。`a = b = c` 按右结合检查，
类型层面按外层 a 的 storage 类型是否兼容内层 Unit 判定（如 a 为 Int 则拒绝）；不全局
禁链式，名称、可变性和 ownership 等检查仍独立成立。
`if (x = 1)` 则因条件要求 Boolean 而拒绝。

p42 的批准结果是**捕获赋值仍拒绝**；审计 §2.6 的 exclusive mutable capture 是另一项设计。
p25 则有两层问题：while 真分支 facts 尚未传播，以及 `var cur = head`/后续移动可能违反
借用来源。C 只解决前者；可重新绑定的 shared borrow cursor 需要独立来源与 loan 合同。

### D–E：数值表示与可观察边界

推荐 Range 为不携带 loan 的普通可存储 Copyable 值，首片 Int/Long，反向区间为空；
可进入局部、参数、返回、字段和容器，各位置需实际验收。Transferable 建议按其纯整数
组成核定，不用该能力声明暗中启用线程。名义类型、闭/半开端点表示与可观察相等是否开放
仍须明确；`first`/`last`/`step` 等公共成员不顺带发布。它与 `View<T>`/`rangeView` 分离。
端点按源码顺序求值一次；闭区间 MAX 处终止，不能先加一溢出。in 仅同型整数、不隐式转换；
具体表面和诊断在冻结时列全。不得因 Range 可存储而自动启用区间下标切片。

checked 转换按数学值域决定：Int→Long、UInt→Long 全可容纳；负 Int→ULong 仍失败，
ULong→Long 的上半值域失败。“扩宽”不能代替 signed/unsigned 检查，须先检查再转换，
且 operand 只求值一次。名称与具体源/目标类型表待冻结，OrNull/截断族延后且不先占名字。
Abort 是既有语言行为，验收区分结果超界与工具失败，有独立超时与终止断言；stderr 新保证
不是 E/D 前置。现整数 checked 与浮点 IEEE754 不变，浮点 math/转换另补后端能力。

实施依赖按具体形态列账：Int/Long 标量已有 lowering 与普通 native 测试，不等于 Range
表示/循环已完成；一般 nullable 构造、参数、返回尚未全闭合，但 Map.get→Int? 等局部路径
已有支持，不能笼统写“Int? 不可 native”。A 的 when(Int)、C 的 nullable class/循环，须在
各自 Spec 先核可执行形态、补受选路径后再记 native 通过，不用宽泛前端通过替代。

### F：构造权限、条目交付和 provider

详细既有候选以[集合剩余 API](collection-api-followups.md)为入口，本页只给版本决定门：

- 推荐首片 MutableMap 按现 put 装填，再 consume 整体移交只读 Map。它是转换，不等同
  非空 `mapOf` 初始化语法；后者仍属 v1 后继设计，不能宣称 consume 已替代其承诺。
  0291 仍须按所选子合同重基、明确启用；其所在 draft 目录不授权实施或自动纳入全部转换。
- consume 必须冻结唯一 owner 移交、源失效、活跃 loan 禁止、目标布局/元数据与最终释放；
  与插入顺序布局共享的表示必须先协调，不能靠重新装填或 clone 伪装整体移交。
- 推荐插入顺序：覆盖已有 key 不改变位置，删除后重插进入末尾。此承诺不等于析构顺序；
  整体 drop 的可观察次序、增长/压缩时 owner 搬移与释放需另行明示。存储实现方案属于
  Compiler Contracts，不能把“索引表+稠密数组”当语言唯一布局，也不能称改造成本已知很低。
- 装填继续遵守 put 的重复 key 与旧/新 owner 交付合同；布局变化后须重新验覆盖、删除、
  tombstone/增长、nullable 值及 Resource 清理，不能用“复用”免验。正常退出须清理已装填
  owner；Abort 不承诺 unwind。遍历另定 key/value shared loan、Copyable 读取与绑定表面，
  provider 退出释放及活跃时 put/remove/relocation/move/drop 冲突；不得丢失 Map 来源。
- 带参工厂后继需先解决 CLI 标准 Pair 可见性/名义身份、完整消费解构与只读构造权限；
  不能按任意双字段结构或名字识别 Pair，不能逐字段偷搬 MoveOnly。条目内部遵守源码参数
  求值次序，不重排命名参数。将来工厂能否按 consume 展开仍须自身合同证明。

## 4. 下一批 v1 与明确延后

下一批另定合同：Box 只读 projection 与 unbox、MoveOnly enum 消费匹配、文本/解析格式化和
同步 IO。Result/后缀 `?`、nullable payload 的实际 frontend/native 及正常退出清理，是这些
API 的真实条件依赖；文件 IO 尤须列 CLI 标准 Result 可见性及 Result/? 原生链路，
仅写出 `Result<String, IoError>` 不代表链路已可交付。
用户要求的 stdin/stdout/stderr、time/sleep/math 仍在 v1 规划，沿
[文本与 IO 候选](text-input-and-io.md)评审，不由本页自动启用签名。

完整 Eq/Hash/Ord/Display 协议另作设计，不能用 Map 现有封闭 Hashable 身份冒充已完成协议。
map/filter 的 owned 结果与泛型 lambda 结果推导可分别交付：显式类型实参、已定型函数值已有
推导路径，审计“R 永远推不出来”不适用于全部调用。若增加两阶段推导，需另定 overload
隔离、Unit/Nothing 与冲突规则。filter 的元素类型可从接收者确定、谓词返回 Boolean，
不能一概把 lambda 结果推导列为 filter 前置。同步、非逃逸 Borrow 回调的 forEach 仍是 v1
承诺，可按代表应用调整优先级；它本身不依赖可变 capture，累加外部变量的写法则另受限制。

本版不纳入可变 capture、borrow var、用户 FFI/unsafe、并发以及 N1b；这不替代各自的长期
版本定位决定。已有 N1a View 不等于区间语法切片；历史审计关于 carrier、线程及 object
能力的陈述须对照当前规则，不作为本次顺手回滚现有能力的理由。顶层 runtime val/var 的
初始化/析构仍未闭合；“仅允许 const val”的接纳面收窄另列待决，不默认为当前规则。

三项额外合同分别待决定是否纳入，不附赠进 A–F：Abort 输出需定字节/换行、短写与失败、
stdout 顺序及最终终止；现 runtime abort 与 CLI 将不可表示退出状态映射为 1 不可混同。
`is E.Case` 从 subject 推断类型实参需定未决类型、部分/显式实参冲突，不是 join 的一部分，
不固定未经验证的既有错误码。顶层 runtime val/var 禁用需定接纳边界与结构化诊断、保留
const val；三者都不能作为纯措辞修正或实施方便的隐含前置。

## 5. 交付门与保义文档轨

文档轨逐条复核审计 C2（诊断码引用）、C5（可信扩展例外）、C8（返回记法）、C9（重复语法）、
C10/C11（示例）与 C15（历史措辞）；只在不改变既有规则的证明成立后作保义修正，诊断类别
或扩展接纳面变化仍须合同批准。泛型 drop 的解释须承接当前“依赖实例”事实与双轨规则，
类型未知时必须保守处理，不能视为纯内存 ASAP；实例化不据此重新安排可观察析构时点。
不默认把全部 T 定义成资源类型，也不以解释补充改变既有时序。

尤其删除冲突草图、引入普通协议和新增容量约束，不能合称无语义变化的整理。
