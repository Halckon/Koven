## 3. 规则文本

### A 错误模型

**A0 原则（Guide 09 新增段首）**

> Koven 不提供异常、`throw`、`try`、`catch` 或栈展开。失败分三类：合法的"没有值"用 `T?`；可预期、可恢复的失败用 `Result<T, E>`；程序不变量被破坏用 abort。标准库中任何可能因调用者提供的输入而 abort 的 API，都必须同时提供一个返回 `T?` 或 `Result` 的版本。

**A1 abort 输出合同（Guide 09、13；D12）**

- abort 时，runtime 先把已由 `println` 交付但尚未写出的标准输出全部写出，再向 stderr 写两行：
  ```text
  abort: <message>
    at <logical-path>:<line>:<column>
  ```
  其中 `<logical-path>` 是 source root 内的逻辑路径（与诊断相同）；行、列从 1 开始，列按 Unicode 标量计数，指向触发 abort 的表达式起点。
- message 规则：
  - `error(message)`：原样输出 message 的 UTF-8 字节，不转义，不追加内容；
  - 编译器触发的 abort 使用固定文本：

    | 来源 | message |
    |---|---|
    | `!!` | `null assertion failed` |
    | 索引越界 | `index <i> out of bounds for size <n>` |
    | 整数溢出 | `integer overflow in <op>`（`<op>` 为 `+`、`-`、`*`、`/` 之一） |
    | 除以零 | `division by zero` |
    | checked 转换失败 | `value out of range for <Target>` |
    | `Map.requireValue` 缺键 | `missing key` |
    | 线程创建失败 | `thread creation failed` |
- 写 stderr 失败时忽略，不重试。写完后进程以 SIGABRT 终止（POSIX shell 中退出码为 134）。
- 任何线程中的 abort 都终止整个进程。

**A2 不 abort 的 API 变体（Guide 04、12；L20、L3b）**

取代 Guide 04 "v1 不提供显式的 wrapping / saturating / checked 变体方法"一句。v1 首批：

- 八种整数类型的 `checkedPlus`、`checkedMinus`、`checkedTimes`、`checkedDiv`、`checkedRem`，签名均为 `fun T.checkedX(other: T): T?`，溢出、除以零或 `MIN / -1` 时返回 `null`。默认运算符 `+ - * / %` 的 checked abort 语义不变；仍不提供 wrapping 和 saturating。
- 八种整数之间的 64 个转换各有 `toXxxOrNull(): Xxx?`，值域与已有 `toXxx()` 完全相同，只把 abort 换成返回 `null`。
- `Array<T>`、`List<T>`、`MutableList<T>` 增加 `getOrNull(index: Int): T?`，仅当 `T: Copyable` 时可用；MoveOnly 元素的非 abort 访问留到 v1.x 的借用访问。

**A3 `main` 可返回 Result（Guide 13；D9、L21）**

- conventional entry 增加两个合法签名：
  ```kotlin
  fun main(): Result<Unit, E>
  fun main(args: Array<String>): Result<Unit, E>
  ```
  `E` 是具体类型并满足 `Display`（见 D），不能是泛型参数。
- `Ok(Unit)`：进程退出码 0。
- `Err(e)`：先写出未写的标准输出，再向 stderr 写 `error: <e.toString()>` 加换行，然后析构 `e`，进程退出码 1。
- `--entry` 显式入口的契约同步扩展为 `() -> Unit` 或 `() -> Result<Unit, E>`。

**A4 Result 必须被使用（Guide 09；D14）**

- 类型为 `Result<T, E>` 的表达式出现在**结果被丢弃的位置**时，Phase 2 报错。丢弃的位置包括：表达式语句、block 中非尾部的表达式，以及结果为 Unit 的 lambda 中的尾表达式。
- 以下都算"使用"：作为 `?` 的 operand；作为 `when` 的 subject；绑定到 `val`/`var`；作为实参或返回值；赋值给字段。
- 错误的 help 给出三种处理方式：用 `?` 传播、用 `when` 处理，或绑定到局部 `val` 以表示有意忽略。
- 本规则只针对 `Result`；其他返回值被丢弃不报诊断。

**A5 退出码与 CLI（Guide 13；D9）**

- 正常从 `main` 返回：退出码 0；`main` 返回 Err：1；abort：SIGABRT。
- `kovenc run` 执行产物后，以子进程的退出状态结束：子进程正常退出码为 n 时 `kovenc run` 也以 n 退出；子进程被信号终止时，以 `128 + 信号编号` 退出。编译失败仍使用现有的构建失败退出码，两者不重叠。
- `exitProcess(code)` 随 IO 与进程接口另行定义，不在本版本。

### B Result 进入内建环境（Guide 02、09；E4）

- 取代 Guide 02 "不得额外自动加载或导入 `Pair`、`Result` 或其他 prelude 名称"一句，改为：

  > 内建环境包含 `Result<T, E>`、`Ok`、`Err`，单文件与 project 相同，不需要 import。除此之外，不自动加载或导入其他 prelude 名称；`Pair` 与 `to` 留待后续版本。

- 这三个名称遵守普通词法遮蔽规则：用户声明的同名 local 遮蔽它们，同一 package 中的同名顶层声明与之冲突时使用既有的绑定冲突诊断。
- Guide 09 中 `Result` 一节的定义不变。

### C 顶层与关联命名空间只接受 `const val`（Guide 05；D4）

- 顶层、具名 `object` body 与 companion body 中的值声明只接受 `const val`。
- 出现运行时 `val`/`var` 时由 Phase 2 报"不支持的顶层运行时值"诊断，主 Span 覆盖 `val`/`var` 关键字。help 给出两条迁移路径：可以常量化就改写为 `const val`；否则改在 `main` 中构造，再作为参数传递。
- Parser 不变，继续产生原 AST 节点；被拒绝的声明不进入 ownership 与 native 产物。原后端 UnsupportedSource 保留为防御性断言。
- 静态不可变存储（候选 G2）及之后的分层见 `global-and-static-state.md` 候选，不在 v1。

### D 值语义协议（Guide 03、04、08、12；D1）

**D-1 能力定义**

| 能力 | 性质 | 用途 |
|---|---|---|
| `Equatable` | 编译器推导的能力，用户不能手动实现 | `==`、`!=` |
| `Hashable` | 同上；`Hashable` 蕴含 `Equatable` | Map 键 |
| `Display` | 预声明 interface：`interface Display { fun toString(): String }`，内建类型已实现，用户类型显式实现 | 字符串插值、`main` 的 Err 输出 |
| `Comparable` | 仅内建，用户不能实现 | `< > <= >=`、排序 |

**D-2 满足条件**

| 类型 | Equatable | Hashable | Display | Comparable |
|---|---|---|---|---|
| 八种整数、`Boolean`、`Char`、`String`、`Unit` | ✓ | ✓ | ✓（`Unit` 除外） | 整数、`Char`、`String` |
| `Float`、`Double` | ✓（IEEE 语义，`NaN != NaN`） | ✗ | ✓ | ✓ |
| `IntRange`、`LongRange` | ✓（沿用序列相等） | ✓ | ✗ | ✗ |
| `T?` | 当 `T` 满足 | 当 `T` 满足 | ✗ | ✗ |
| `value class` | 全部字段满足时自动满足，逐字段按声明顺序比较 | 全部字段满足时自动满足 | 仅当显式实现 | ✗ |
| `enum class` | 全部变体的全部 payload 满足时自动满足：先比较变体，再逐字段比较 | 同左 | 仅当显式实现 | ✗ |
| `Box<T>` | 当 `T` 满足，比较内部值 | 当 `T` 满足 | ✗ | ✗ |
| `Array<T>`、`List<T>`、`MutableList<T>` | 当 `T` 满足，长度相同且逐元素相等 | ✗ | ✗ | ✗ |
| 普通 `class`、`Rc<T>`、`Map`、函数类型 | ✗ | ✗ | 仅当显式实现（class） | ✗ |

**D-3 运算符规则**

- 取代 Guide 03 中 `==`/`!=` 的操作数规则：两侧为同一类型 `T` 且 `T: Equatable`，或 `T` 与 `T?`、或任一侧为 `Nothing`/`Nothing?`；否则使用 L0085。普通 `class` 的 `==` 因此成为类型错误，迁移方法是比较具体字段或写显式方法。
- `==` 以 Borrow 方式读取两侧，不移动、不复制 MoveOnly 值。
- Guide 12 中 Map 键的要求由"内建 capability `Hashable`"扩展为本节的 `Hashable`；`Int`、`Boolean`、`Char`、`String` 的既有规则不变。
- 泛型上界可以写 `<T : Equatable>`、`<T : Hashable>`、`<T : Display>`，在泛型体内作为能力证明；未约束的 `T` 不得假设满足。

### E 字符串插值（Guide 04；D2）

- `"...${e}..."` 中的 `e` 必须满足 `Display`，否则 L0085。
- 求值顺序：各插值表达式从左到右各求值一次，以 Borrow 方式调用 `toString()`，按顺序拼接成新的 owned `String`；临时值在整个字符串表达式结束后按既有规则析构。
- 嵌套字符串与插值的解析规则不变。`println` 的参数仍为 `String`；打印数值请写 `println("${n}")`。

### F 闭包可变捕获（Guide 07；D7）

- 非 move 闭包的 body 中对捕获的局部 `var` 赋值时，该捕获由 shared loan 改为**独占借用**。此时该闭包称为 mutating closure。
- mutating closure 的使用限制与 borrowed closure 相同（不得 return、写入字段、交给 Value 参数或被 escaping move closure 捕获，违反时 L0137），另有两条：
  - 闭包值存活期间，被捕获的 `var` 不能在闭包外读写或借用，冲突使用既有的借用冲突诊断；
  - 闭包值不满足 `Copyable`。
- 只允许捕获本函数的局部 `var`；`inout` 参数、字段和 `this` 的写入不在本版本。
- move closure 不变：捕获的仍是 snapshot，不能赋值。
- 典型写法：
  ```kotlin
  var total = 0
  items.forEach { x -> total = total + x }   // forEach 随集合 API 另行启用
  ```

### G companion 语法（Guide 08、14；D13）

- 关联命名空间的声明写作 `companion { ... }`，语义与 v0.45 的 `companion object { ... }` 完全相同：不产生对象，没有初始化，不实现接口，只能包含 `const val` 与关联函数。
- `companion object { ... }` 改由 Parser 报错，并给出删除 `object` 的修正建议。产品尚未发布，不保留兼容别名。
- 语法索引同步更新；`Type.member` 的名称解析不变。

### H 按名解构（Guide 11、12；D15）

- `val (a, b) = expression` 的源类型为 value class 时，每个绑定名必须等于该类型的一个主构造器字段名，并且每个字段恰好出现一次；书写顺序不限。
- 未知名称、重复名称、缺少字段分别使用 Phase 2 诊断；分量绑定按名称取对应字段，Copy/Consume 判定不变。
- 仍不支持重命名、`_`、嵌套模式和部分解构。`for ((key, value) in map)` 的双分量 Map 遍历不受影响，它不是 value class 解构。

### I Guide 瘦身（Guide 13；D6/L14）

- "受控底层能力与 Unsafe 边界"整节（`extern "C"`、`RawPtr<T>`、`unsafe { }`、标准库特权）移到 proposals。Guide 13 只保留一句：

  > v1 的用户源码中没有 `unsafe`、`extern` 与裸指针；标准库如何借助 runtime 实现属于实现细节，不是语言承诺。

### J 受限线程（Guide 07、10、13；D5）

本包取代 Guide 13"线程、Channel 与 Move Closure"一节的 API 部分，`Transferable` 推导规则不变。

```kotlin
val worker: Thread<Int> = thread(move { compute() })
val result: Int = worker.join()

val (sender, receiver) = channel<String>()
val producer = thread(move { sender.send("hi") })
val text: String? = receiver.receive()
```

- **创建**：`fun <T> thread(own body: move () -> T): Thread<T>`，要求 `T: Transferable`，body 的全部捕获满足 `Transferable`。创建失败时 abort（A1）。
- **join**：`fun Thread<T>.join(): T` 消费 handle，阻塞直到 body 返回并交付结果。
- **隐式 join**：`Thread<T>` 被析构而尚未 join 时，析构过程阻塞到线程结束，并析构其结果。v1 不提供 detach。因此函数返回时，它创建且仍持有的线程都已结束。
- **channel**：`fun <T> channel(): Channel<T>`，其中 `value class Channel<T>(val sender: Sender<T>, val receiver: Receiver<T>)`，配合 H 的按名解构使用。
  - `Sender<T>.send(own value: T): Boolean`：接收端已析构时返回 `false`，并析构 `value`；
  - `Sender<T>.clone(): Sender<T>`：显式复制发送端，形成多生产者；
  - `Receiver<T>.receive(): T?`：阻塞直到收到值；全部发送端都已析构且队列为空时返回 `null`；
  - `Receiver<T>` 不可复制。
  - `T: Transferable` 时，`Sender<T>` 与 `Receiver<T>` 满足 `Transferable`；`Thread<T>` 不满足。
- **可见性**：`join` 返回时，线程中的全部写入对调用者可见；`send` 之前的写入，对收到该值的 `receive` 之后可见。
- **不在 v1**：共享内存、`Mutex`、原子类型、`Arc`、`Shareable`、scoped 借用线程、线程池、async。
- **验收**：第七个验收程序（多线程词频或管道），不计入 v1.0 硬门槛。

## 4. 不纳入本版本

- `exitProcess`、文本 API、文件与标准输入输出：随 IO 版本定义（L5、L6）。
- `Pair`、`to`、`mapOf("a" to 1)`：随 S6。
- `forEach`/`map`/`filter` 等集合 API：随 L16，依赖本版本 F。
- MoveOnly enum 的消费式匹配（L7）：单独评审。
- Kotlin 的 companion extensions、`when` guard、集合字面量、context parameters、rich errors 的联合类型。

## 6. 已按建议定下、如需调整请在启用前提出

- `Display` 的方法名用 `toString()`（贴近 Kotlin），而不是新名字。
- `Sender.send` 在接收端消失时返回 `false` 并丢弃值，而不是返回 `Result<Unit, T>` 交还值（后者更严格，但每次 send 都要处理）。
- 按名解构要求列出全部字段，不支持部分解构。
- must-use 只针对 `Result`，是错误而不是警告。
- `kovenc run` 对被信号终止的子进程以 `128 + 信号编号` 退出。
