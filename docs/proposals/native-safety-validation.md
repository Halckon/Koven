## 开放覆盖与验收条件

| 原项 | 尚需独立选择或扩大证明的范围 |
|---|---|
| S01 | 0266之外的平台、Koven IR UBSan等；用户函数/runtime/drop glue均须有故意错误及干净对照，工具不支持明确未覆盖 |
| S02 | 新语义片的独立输出/owner资源oracle；正常无环清理与仍活loan分别验证，内容正确不代替资源正确 |
| S03 | 0269之外的有效/非法生成域；Map/closure/thread随正式支持扩展，已知缺陷检出与误报分开 |
| S04 | 新域seed重放与缩减；保留原始/最小失败和编译器/环境/命令身份，不靠超时变化冒充缩减 |
| S05 | 共同支持输入的差分、Abort不展开、Rc强环及预算退出分类；旧二进制不是唯一oracle |
| S06 | 新接线缺检测器/失败/跳过负向门禁及源码大小、时间、内存、子进程、总量预算 |
| S07 | M4c外审：固定SHA、假设/威胁边界、可重放材料、发现归因与逐项处置 |

只扩选定范围，不重新认证全部历史。资源预期不能全部由被测drop plan生成；先定位frontend、
lowering、runtime、检测接线或oracle，再以原先失败的回归修复。不以减少样本/排除seed消除问题；
并发检测等待M6合同，ASan不证明无数据竞争。

## 外审与启动条件

明确范围内可准备材料；邀请、发送源码/报告和披露发现需对应授权。检测器、生成预算和CI频率
由所选Spec封闭；本页不授权注入、校准或扩大实验。首次preview只要求正式发布合同选定门槛，
大规模随机和外审不是无限隐含前置；样本或外审均不构成完整内存安全证明，不同时承诺模型检查或认证。

## 与演进总纲的对齐（2026-11-10 增补）

后续候选设计会扩大需要检测覆盖的面，届时各自的 Spec 应回到本页选择检测手段，本条不授权任何实验：

- 标准库以 unsafe 自行实现容器与 IO（[之四](evolution-04-route-capability-unsafe-suspend.md) U2、[之七](evolution-07-concurrency-async-io-ffi.md) IO2）之后，
  地址与泄漏检测的对象从 runtime 扩展到 Koven 源码写成的库。
- 共享内存并发（之七 S2）需要数据竞争检测；现有检测首片不覆盖。
- 由参数模式生成后端别名属性（[之八](evolution-08-compiler-ir-escape-simd-selfhost.md) §3.2）一旦与别名合同不符即为未定义行为，应有针对性的差分或检测手段。
