## 1. 四组最少补充选择

以下为可一次审阅的具体方案，不要求用户决定内部数据结构或实现算法。

| 组 | 推荐候选 | 必须确认的边界 |
|---|---|---|
| A/C 类型与循环 | 采用 §2 的封闭 join 与最小保守 while；保留原 statement 接纳面与 if/when 不同错误码 | 不额外开放混型 if statement，不从 while 出口新增 false/break 收窄；更精确循环分析后续 |
| D Range 身份与相等 | 公开编译器绑定 `IntRange`/`LongRange`；两种区间运算均产生对应类型；普通 Copyable/Transferable | 建议按升序元素序列相等，同型空区间相等、`1..2 == 1..<3`；该公共身份与相等合同需明确确认 |
| E 转换表面 | 八整数 builtin 之间完整 8×8 checked 转换，含同型 identity；零参 intrinsic 成员 `toByte/toShort/toInt/toLong/toUByte/toUShort/toUInt/toULong` | 名称、完整类型族与同型转换需明确；不启用 const 求值、OrNull/截断或其他类型转换 |
| F Map 绑定与销毁 | 仅 `for ((key, value) in map)` 两个 shared 绑定，不创建 Pair；consume 首片仅 owned 本地根 binding | 建议首片不加 `_` 跳过绑定或单 entry 值；临时、字段、元素、Borrow/Inout receiver 拒绝；条目整体销毁的顺序保证须选定（见 §4） |

D 的序列相等与 F 的销毁次序保证边界是可观察语义；不能由布局作者决定。其余推荐若需改动，应在
current 切换前一次修订。本页不自动启用整个 0291 或把非空 mapOf 后继取消。

## 2. A/B/C 拟替换的规则正文

目标：Guide03“基础表达式/Expected Type”及 Guide06“流事实/Value Context”。

- A：value-context if/when 有 expected type 时逐分支检查兼容性，不匹配沿用 L0084。
  无 expected type 时只允许：相同规范化类型；Nothing 与另一类型取另一侧；null 的
  Nothing? 与 T 合成 T?；T 与 T? 取 T?；同一 enum 实例的 case/root 合并为该 root。
  nullable 提升只沿既有 assignability，不做数值 widening、泛型协变或隐式 Any 装箱。
  其余已知类型拒绝：if 保留 L0089，when 保留 L0112。Error 抑制同根级联，Deferred
  保留真实原因，不参与成功判定；全部可达分支不正常返回时结果仍为 Nothing。
- A 的上下文边界：statement when 及无 else 的 if 维持 Unit；有 else 的 if 仍检查
  分支 join，不因结果被丢弃而新接纳混型分支。when 的 value 穷尽要求保持不变。
- B（已批准）：已解析简单变量的普通 `=` 以变量声明 storage 类型检查 RHS；成功后结果
  为 Unit，RHS 检查后清除目标全部流事实。分组目标沿既有透明语法；不重新推导 storage
  类型。名称、可变性、capture、loan 和 move 规则保持原阶段。compound、字段、下标不扩。
  Unit 可作兼容值上下文与 lambda 尾值；链式赋值按右结合及外层 storage 兼容性检查，
  不全局禁止。该项不授权修改捕获变量。
- C：进入循环头时清除可能被循环写入或回边改变的旧收窄；每次检查条件时，只向 body
  传入条件为真所证明的稳定 place 事实。赋值先检查 RHS 再 kill；normal/continue
  不将本轮收窄直接带回头。循环退出不新增 condition-false 或 break 推导事实，既有
  必须 kill 的来源继续失效。稳定不可变来源保留规则不变；不做固定点、borrow cursor
  或借用 MoveOnly 移出的接纳扩展。必须覆盖零次执行、嵌套 loop 与回边写入反例。

## 3. D/E 拟新增的规则正文

目标：Guide03 类型身份、Guide04 运算与 Guide12 provider；具体原生布局归 Compiler Contracts。

- D：Int/Long 同型端点 `a..b`、`a..<b` 分别构造对应 Range，端点从左到右各求值一次；
  不同型拒绝，不隐式转换。a 大于 b 时两者为空，a 等于 b 时闭区间一元素、半开为空。
  in/!in 只接受匹配的整数元素与 Range，返回 Boolean。for 按升序每轮交付 Copyable
  整数值，闭区间达到最大端点即结束，不对 MAX 再加一。正常退出沿用 loop 清理规则。
- Range 不携带 loan，可用于局部、参数、返回、字段及容器；无公开构造器、first/last/
  step/size/hash/display、切片或开放 Iterator 协议。Copyable/Transferable 不启用线程。
  相等按 §1 最终选择写入，不能继承“同型均可比较”而没有动态定义。
- E：上述每个成员只作用于八种整数 builtin。receiver 求值一次；数学整数落在目标
  闭值域内则返回目标类型值，否则沿既有 Abort 终止。不先截断再检查，不按位宽判断
  是否总成功：负 Int→ULong 仍失败，UInt→Long 全可表示。此成员身份不开放用户扩展
  或通用重载；Float/Double、Char、Boolean、String、nullable 和常量求值均不因它启用。

## 4. F 拟新增的规则正文与未决销毁合同

目标：Guide12 Map/provider，必要时 Guide02/06 仅补既有 for 解构表面的精确接纳范围。

- 推荐插入序遍历；覆盖既有 key 不改位置，删除重插进入末尾。该保证不限制实现选用
  何种索引、缓冲区或压缩算法，不自动规定 drop 顺序。
- `for ((key, value) in source)` 只允许 Map/MutableMap 的两个 shared 绑定；Copyable
  普通读取可复制，MoveOnly 不能移出或逃逸。source 只求值一次，temporary source 的
  owner/loan 延续到 provider 结束；不引入可存储 entry 或 Pair 类型。
  本轮局部清理、element loan、provider/source loan 与 temporary owner 的退出顺序
  复用顺序 provider 的正常/continue/break/return 规则；不能为返回来源提前结束保护。
  活跃遍历拒绝 put/remove/consume/relocation/整体 move/drop；共享查询及嵌套共享遍历可用。
- `MutableMap<K,V>.consume(): Map<K,V>` 仅从 owned 本地根 val/var 整体移交同 K/V；
  成功后源不可再使用，活跃借用拒绝。无 clone、重新装填或条目 drop；最终仅结果承担
  唯一释放义务。暂不接纳临时 receiver，可先绑定后调用；不启用反向/复制转换。
- 整体销毁只保证仍由 Map 拥有的 key/value 各自精确销毁一次，不保证不同 entry 之间
  或同一 entry 内 key/value 的先后；这项保证边界待确认。现 Guide 未承诺内外先后，
  现实现 key 先 value 不提升成语言保证；布局改造仍需报告实际可观察次序变化。
  插入遍历顺序不构成整体 drop 次序。若要新增整体插入序/逆序或 key-first 保证，另行批准。
- put/remove 的既有提交、移出和唯一销毁合同保持；Map 布局变更必须重验 Resource、
  nullable 值与活跃 loan。Map 容量上限（C14）仍未纳入，不从 provider 索引偷加新上限。
