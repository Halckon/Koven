# IO 资源借用、责任交接与清理：设计安全原则

讨论要回答的问题：异步操作可能继续访问资源、责任可能转移、执行可能失败时，什么时候可以清理或复用资源；无法证明时如何保持安全。

## 2. 原则

### 2.1 三个维度分开判断

外部访问事实、清理责任、清理执行进度是三个不同的问题，不能用一个状态互相替代。

- 责任可以在外部访问终结之前交接。
- 执行清理或复用须同时具备三项：可靠的外部访问安全证据；合法的清理责任；本地别名与共享资源条件成立。

### 2.2 接管与终结必须有证据

- 逐请求区分“已终结”与“从未接管”，并保留证据的来源和适用范围。
- 提交失败、取消请求、没有收到通知、请求 abort，都不自动证明外部访问已经结束。
- 批次中某些请求有证据，不能替未获证的请求放行。
- 证据丢失不改变历史事实，也不能推翻其他仍可靠的事实。但观察者若已无法取得足够的访问安全证明，就必须按未知处理，禁止相关的释放或复用。

### 2.3 身份、交接与迟到通知

- 责任和通知必须绑定到可验证的请求身份及代际。
- 迟到的通知先确认属于哪个请求，再判断是重复、重排、错投还是证据冲突。
- 代际可以防止错投，但不能阻止旧 IO 对已复用的内存继续写入，所以不能代替资源保活。
- 责任持有者失败时，后继不能只是“被点名”：须在声明的失败域内证明存在可激活、可观察的有效交接路径。
- 证据重放或记录重试本身不产生新的清理执行权。

### 2.4 清理进度与恢复

- 执行标记的确认丢失、记录撕裂、已做未记、已记未做时，不能推断副作用一定没有发生，也不能直接宣称完成。
- 安全续做必须由具体资源协议证明。可以是：可重试的幂等性；能反映实际结果且排除恢复竞态的稳定身份查询或去重；同时解决副作用与恢复证据一致性的原子协议。
- 单独对记录做 CAS、原子写或写前意图记录，不足以证明外部副作用与记录一致。
- 单步幂等不证明整个后续序列可以安全重放，更不等于 Discharge。
- 进度用向量、标量或其他表示，不是统一前提。所选协议须说明状态含义、完整性、可观察性与失败域。

### 2.5 abort 窗口与本地资源

- 请求 abort 不等于实际终止。终止之前，必须继续保证外部可能访问的资源不被释放、不被复用、必要的授权不被撤销。
- 这个窗口需要后端对访问范围、责任持有者以及运行时与资源合同作联合证明；分配器或外部监督者若参与，也须说明各自的保证。
- 仅保留字节、假定线程很快停止、仅停止其他线程，都不是充分证明。
- 进程已经终止后，不能要求它继续观察或清理。
- 本地别名、共享 buffer、资源身份和授权可以单列为检查项，并作为所有相关清理与复用路径的共同前提；证明不足时拒绝相关动作。

### 2.6 与 Origin 的关系

两者可以共享义务、责任与交接的词表。但 Origin 的依赖与合流证明，和 IO 的外部访问、并发及失败域证明，仍须各自完成。
不能因为状态形状相似，就声称证明一次即可覆盖两个协议。

## 3. 尚未决定与实施门槛

- **失败政策（2026-11-14 所有者选定方向）**：证明不足时保留资源，不释放、不复用；仍可能存在外部访问、且已没有安全责任路径时，终止进程。
  两步有先后：“无证明则不释放”是默认，进程终止只用于连保留也没有责任者的情形，二者不等同。
  进程终止本身仍须满足 §2.5 的终止窗口证明。保留或隔离的其他替代方案不排除，但须各自给出证明后另行批准。
  这是候选方向，写入 Guide 或 Spec 仍走正常流程。
- **后端证明，待各后端提供**：请求关联、接管与终结证据、恢复者激活、副作用恢复、本地资源安全、终止窗口。未认领的证明责任如实记为待认领。
- 这组原则收尾的是设计安全原则与验收方向。它不代表具体后端已验证或生产实现已完成。
