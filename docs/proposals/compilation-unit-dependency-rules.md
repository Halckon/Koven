# 编译单元依赖、接口产物与语言版本规则提案（之十一 J45–J47）

> **性质**：非规范候选设计（阶段一文档先行提案） · **状态**：未启用（不修改 Guide v0.47，不批准 Spec/ADR，不授权实现） · **读取时机**：起草跨编译单元构建、接口产物（声明清单）格式、项目清单 `language_version` 字段，或核对 J37 一致性规则与标准库三分边界时 · **唯一真源**：本页将[演进总纲之十一](evolution-11-failure-interfaces-units.md) §3（J45–J47）展开为可评审的规则草案，并衔接[之三](evolution-03-route-existential.md) §6（J37 一致性）、[之六](evolution-06-text-globals-extensions-metadata.md) §5（J13 声明清单）、[之十三](evolution-13-implementation-roadmap.md) §3（Z8）与 [Guide 02](../guide/02-names-files-packages.md)

本文不修改或启用任何 Guide 规则，不批准 Spec/ADR，不授权实现。现行 Guide 02 已规定 `package` 为命名空间、编译单元为 driver 一次交付的源文件集合及三级可见性（`public` / `internal` / `private`），但尚未规定编译单元之间的依赖图约束、接口产物契约与语言版本切换规则。

## 1. 两层依赖规则（J45）

Koven 将“命名空间”与“编译与分发边界”严格分离为两层：

| 层级 | 对应概念 | 循环引用规则 | 理由 |
|---|---|---|---|
| **内层（命名空间）** | 同一编译单元内的多个 `package` | **允许循环引用** | `package` 只是目录与命名空间组织；强行禁环会迫使开发者按依赖拓扑拆分本应内聚的类型（如 AST 节点与访问者） |
| **外层（编译与分发）** | 多个编译单元（unit）之间的依赖图 | **必须严格无环（DAG）** | 分别编译、增量构建、确定链接次序、J37 一致性规则与[之九](evolution-09-architecture.md) A3 的共同前提 |

### 1.1 编译单元依赖图校验合同

1. **先验环检测**：构建计划在启动任何编译单元的 Phase 2（类型检查）之前，必须基于当前清单与实际源码依赖边构造有向图并检验无环；若发现环，必须输出完整的最短依赖环路诊断（例如 `unitA -> unitB -> unitC -> unitA`），不得复用旧缓存产物掩盖新引入的环。
2. **可见性边界**：
   - 跨编译单元仅可见目标单元导出的 `public` 符号；
   - `internal` 严格限定在声明它的同一编译单元内，不进入跨单元导出接口；
   - `private` 沿用 Guide 02（源文件或 classifier 成员内可见，见 [U0 合同](unsafe-aliasing-contract-outline.md) TR4）。
3. **打破跨单元环的标准模式**（文档约定，不新增语言特性）：
   - **依赖倒置**：把两个单元共同需要的 `interface` 与数据契约抽到第三个基础单元，两侧只依赖该基础单元；
   - **单元合并**：若两个单元在语义与发布周期上高度耦合，直接合并为同一编译单元，内部用多个 `package` 分层。

## 2. 经接口产物依赖与导出合同（J46）

当编译单元 A 依赖编译单元 B 时，A 的编译**只读取 B 产出的接口产物（Interface Artifact）**，不直接读取 B 的私有实现源码。该产物与[之六](evolution-06-text-globals-extensions-metadata.md) J13（外部代码生成器声明清单）及 LSP 跨单元查询共用同一稳定信息源。

### 2.1 接口产物最小内容清单

| 段 | 必须包含的内容 | 不得包含或泄漏的内容 |
|---|---|---|
| **头部与身份** | 产物格式 schema 版本、编译器 ABI 版本、单元逻辑名、声明的 `language_version`（J47）、直接依赖列表及其内容哈希 | 本地绝对路径、构建时间戳等非确定性噪声 |
| **公开声明签名** | 全部 `public` 类型（`class` / `value class` / `enum class` / `interface` / `object` / `view class`）、字段布局与可见性、函数签名（含 `own`/`borrow`/`inout` 模式、接收者模式、`from`/`flows` 合同、能力边界与 `deinit` 存在性） | `internal` / `private` 顶层声明及普通非泛型函数体实现 |
| **泛型与内联体** | 供调用方单态化所需的 `public` 泛型函数/方法体，**以及其传递调用到的全部 `internal`/`private` 泛型体（放入仅供单态化消费、下游不可直接按名引用的受控内部段）**；过渡期可为归一化源码或 AST，所有权图 IR3 稳定后切至序列化所有权图，具体格式走独立 ADR | 与任何导出泛型单态化路径无关的普通私有函数体（非泛型私有辅助函数仍只导出内部链接符号，不导出函数体） |
| **常量求值依赖（KB9）** | `public const val` 的编译期求值结果及跨单元常量求值所需的可求值构造信息（之六 J6 / J8） | 运行时初始化逻辑（Koven 禁止 main 前用户代码） |
| **一致性索引（J37）** | 该单元内声明的全部 `(Type, Interface)` 实现表，供下游快速做孤儿与重叠检查 | 扩展函数（之六 J10：扩展函数不构成 interface 实现） |

### 2.2 缓存失效与确定性要求

- **内容寻址**：接口产物内容哈希覆盖全部公开签名、公开泛型体及其传递依赖的私有泛型体；只要 B 的接口产物内容哈希未变（例如只修改了 B 中非泛型函数的私有实现体），依赖 B 的单元 A 的前端与类型检查产物**无需重编**（链接期更新目标码即可）。一旦被公开泛型传递调用的私有泛型体发生变化，接口产物哈希必然改变并触发下游受影响单态化重编。
- **版本不兼容快速失败**：若读取到 schema 版本或编译器 ABI 版本不匹配的旧接口产物，必须明确报版本不兼容并触发重新生成，不得静默忽略或降级读取。

## 3. 按编译单元声明语言版本（J47，对齐 Z8）

为避免启用新保留字或语法演进演变成全生态的破坏性切换，语言版本按编译单元显式声明（落实[之十三](evolution-13-implementation-roadmap.md) §3 Z8 与 [v1 冻结约束](v1-freeze-decisions.md)）。

### 3.1 清单声明与词法隔离

1. **清单字段（Z8）**：v1 起 `project` 清单即包含 `language_version` 字段（例如 `language_version = "1.0"`），即使 v1 阶段只有一个合法取值。未声明时在 v1.x 可按默认基线解释，但跨版本混编须显式声明。
2. **保留字与表面语法按单元隔离**：在版本 `V2` 新启用的关键字（如未来的上下文关键字提升或新保留字）只在声明了 `language_version >= V2` 的编译单元内生效；仍声明 `V1` 的旧单元可以继续把该词用作普通标识符（如变量名、函数名、字段名）而无需同步迁移。

### 3.2 跨版本调用边界合同

当声明版本为 `V2` 的单元 A 调用声明版本为 `V1` 的单元 B（或反向）时，遵循**双向独立检查**原则：

- **声明端按声明版本检查**：B 的源码与导出的接口签名按 B 自己的 `language_version` 词法与语义规则检验；
- **调用端按调用版本检查**：A 中的调用表达式按 A 的 `language_version` 规则解析；若 B 导出的符号名恰好在 A 的版本中成为关键字，A 可通过反引号转义或既定转义语法引用（具体转义细则归入启用新关键字的语法提案，须经 F5 文法增量门禁）；
- **语义合同不变**：语言版本隔离的是表面语法、保留字与可逆默认行为，不得破坏统一 ABI、内存安全或所有权不变量。

### 3.3 回答之十一 §3.4 开放问题：依赖的最低语言版本要求

- **建议结论**：**默认不强制传递语言版本要求**——只要 B 的接口产物 schema 与当前编译器兼容，声明 `1.0` 的单元 A 可以依赖声明 `2.0` 的单元 B，反之亦然。
- **例外与显式约束**：仅当 B 导出的公开签名使用了 `1.0` 无法在调用点表达的语法或能力（例如需调用方显式书写某新语法标记）时，接口产物应标注 `min_caller_language_version`，编译器在 A 解析 B 的接口产物时直接给出清晰的版本升级诊断，而非报晦涩的语法或类型错误。

## 4. 与 J37 一致性规则、标准库三分及测试单元的衔接

本节补齐[演进总纲之十一](evolution-11-failure-interfaces-units.md) §3.4 留下的其余两项开放问题，并与[之三](evolution-03-route-existential.md) §6 的 J37 一致性规则对齐：

### 4.1 J37 一致性规则（孤儿检查）与编译单元无环的配合

- 严格对齐[之三](evolution-03-route-existential.md) §6 与[之十一](evolution-11-failure-interfaces-units.md) §3.3：对任意 `(ConcreteType, Interface)`，接口实现只能写在 **`ConcreteType` 的声明处**（与该类型声明绑定），或 **`Interface` 所在的编译单元内**（不允许在类型所属编译单元的其他文件为该类型零散追加外部接口实现）。
- 由于 J45 保证编译单元依赖图严格无环，`ConcreteType` 所在单元与 `Interface` 所在单元不可能互为依赖；因此不会出现同一对 `(Type, Interface)` 在两个不同编译单元里各自声明实现而彼此不可见的冲突。
- 若在 `Interface` 所在编译单元内跨多个 `package` 对同一对 `(Type, Interface)` 声明了重叠实现，由该编译单元自身的类型检查直接以一阶合一重叠检查拒绝（之三 J37）。

### 4.2 标准库三分（之十 W6）的编译单元 DAG

按[之十](evolution-10-coverage-gaps.md) §7.5 与[之十三](evolution-13-implementation-roadmap.md) §4.4，标准库在 U2 容器库化前切分为三个独立编译单元，天然构成严格无环链，均受 J45–J47 约束：

```text
koven.core（无堆、无 OS 依赖：基础类型、Slice、StringView、Option/Result、Iterator、核心能力接口）
    ▲
koven.alloc（依赖 core + 分配器合同：Box、String、List、MutableList、Map、Arc/Rc）
    ▲
koven.std（依赖 core + alloc + 平台层 PL2：同步/异步 IO、线程、时钟、网络、子进程）
```

该切分使嵌入式/无堆目标（阶段六 U4 freestanding）只依赖 `koven.core`，而不会把 OS 或堆分配符号拉入依赖图。

### 4.3 测试代码是否构成独立编译单元（回答之十一 §3.4 开放问题）

建议采用**双轨区分**（与 Rust 单元/集成测试分层一致，避免 `internal` 过度暴露或白盒测试写不出来）：

| 测试形态 | 归属编译单元 | 对被测单元 `internal` 的可见性 | 用途 |
|---|---|---|---|
| **白盒单元测试**（同单元 `test` 源集） | 与被测单元同属一个编译单元（测试构建模式） | **可见**（遵循 J45 内层规则） | 验证内部数据结构、不变量与私有辅助逻辑 |
| **黑盒集成测试**（独立测试目标） | 独立编译单元，仅经 J46 接口产物依赖被测单元 | **不可见**（仅见 `public`） | 验证导出接口产物完整性、J37 一致性与跨单元可见性边界 |

## 5. 后续落地切片建议

本提案本身不授权实现；进入阶段一/阶段二工程实施时建议拆为三个独立交付：

1. **v1 清单预留（Z8）**：在 v1 发行前于 `project` 清单 schema 中保留 `language_version` 字段并锁定校验（仅允许当前 v1 版本值）。
2. **接口产物 ADR 与最小导出（阶段一末 / 阶段二初）**：确立接口产物序列化格式与内容哈希协议，先支持单向 DAG 校验与 `public` 声明导出，暂以归一化源码承载公开泛型体。
3. **跨单元所有权图导出与多版本共存（阶段二 IR4 之后）**：将泛型导出体切换为所有权图表示，并在引入首个需要新保留字的语言版本时启用 J47 词法隔离与 `min_caller_language_version` 校验。

**离线原型验证（2026-11-28）**：J45 两层依赖图与最短环路检测、白盒/黑盒测试可见性、J37 孤儿检查 / R0–R1 禁一揽子实现 / 标准一阶合一重叠检查、J46 接口产物确定性内容哈希（含传递调用私有泛型体失效与 schema 不兼容快速失败），以及 J47 保留字隔离与 `min_caller_language_version` 校验，已在非规范原型 `scripts/loan_kernel/coherence_unit_model.py` 与 `scripts/tests/test_coherence_unit_model.py`（5 组单测）中固化可复跑。
