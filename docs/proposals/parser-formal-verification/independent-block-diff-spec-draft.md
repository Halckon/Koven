# F4a 候选 Spec：普通块表达式离线差分

> **性质**：非规范交付合同草案 · **状态**：已由 SPEC-0478 承接实施，本页保留规划期草案 · **读取时机**：回溯 F4a 首片候选交付范围与放行条件时 · **唯一真源**：正式实施以 [SPEC-0478](../../archive/specs/0478-independent-block-difftest.md) 为准

## 目标与边界

Phase 1。将[已经实跑的原型](independent-block-diff.md)变成可从干净 checkout 复跑的离线测试。
只比较普通 `parse_block` 中的名称、前缀减号、二元减法、普通成员访问和元素边界；使用现行 Guide v0.47。
本片不改生产 Parser、Lexer、Formatter、公开 API、Guide 或 required CI；不覆盖 D1–D3、完整表达式、
诊断恢复或 Tree-sitter。与 SPEC-0477 的同 Parser 往返测试是两条独立证据，不依赖其合并。

## 交付与验收

| 合同 | 通过条件 |
|---|---|
| 同输入、独立解析 | 参考侧只接已验证的 `Token / NL / EOF`，不接 AST、stop set 或任何续行结论。生产侧只用公开入口；以独立手填或模板预期验证两路，不只检查一致 |
| 固定语料 | 复用原型的 16 个输入：11 个精确结构，2 个完整入口语法拒绝，2 个词法拒收，1 个范围外；四类数量分别断言。两条语法拒绝不比较恢复 AST；内部错误、超时、预期内但投影不支持的节点均使运行失败 |
| 可枚举正例 | 复用原型四个模板，每个名称槽独立填 `a` 或 `b`，得到 32 个唯一输入；逐例验证明确预期绑定与完整消费合同。不以根 Span 代替消费验证 |
| 投影与位置 | 保留有序元素、名称、节点和子边角色；不比较 arena ID 或绝对位置。独立断言 Span／词法 owner、符号拼写、source identity；位置平移对照保持相同结构 |
| 故障检出 | 复跑原型的四个词法流故障及三个结构故障，逐例断言预期的失败层。刻意注入的参考文法歧义必须被报告，不能默认选第一棵树 |
| 可复现 | 从干净 checkout 以一条文档化命令运行；空虚拟环境或无依赖的启动路径不能引用临时本机文件。两次同输入有相同结果与稳定顺序；macOS AArch64 和项目支持的 Linux 宿主分别验证。缺工具、证据不全或未运行要明确失败或标未验，不显示绿色通过 |

## 实施顺序与放行点

1. **批准离线运行方式**：优先评估原型用的固定 Lark Earley，保留输入级歧义见证。接入前按
   [依赖治理](../../development/dependencies.md)核对许可、包来源与固定方式、兼容、安全和成本；不把联网安装
   藏进 `cargo test`。如不能接受外部工具，另行评估零新增依赖的显式前瞻对照，且不得声称它具备 Earley 的
   歧义检测能力。先定方案，再指定持久入口和文件位置。
2. **批准交付并开分支**：按仓库治理编号，从 `main` 开独立 `feature/spec-<id>`，使候选合同进入正式交付流程。
3. **锁定一个端到端正反对照**：在所属前端测试边界内固定 `a\n-b` 和 `a/*雪\r\n*/.b`，
   先证漏发换行与截断 CRLF 分别失败，再做最小流交接和两路结构比较；不新增通用差分框架。
4. **补齐有界语料和本地复现**：纳入其余固定输入与模板，运行负对照、文档检查和同批生产回归。
   在支持的两类宿主验证同一命令，记录版本、计数和未运行项；不提交原始日志或重复转储。
5. **完成分支交付**：PR 准备好后才触发既有 CI 门禁，不因离线试验替代或削弱门禁。

[Lark 离线接入审查](lark-offline-audit.md)建议以固定 SHA-256 的 wheel 有条件采用，并给出首片输入上限与
进程截止时间候选。wheel 的参考侧已在 macOS 与 Linux 容器中验证；正式入口、所选 Python 版本和 Linux
生产差分仍待验证。本草案不授权实施，不修改 SPEC-0477 的状态。
