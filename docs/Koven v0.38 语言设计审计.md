## 三、v0.38 新增内容的审计

**1. 13 的 unsafe 小节：方向对，但还不是规则。**

- **无语法**：
  - 01:68 仍写 `unsafe` "没有使用它的产生式"。
  - 08 的 `declaration_modifiers` 只有 visibility，08:372 把 `extern`/`unsafe` 列为不支持的修饰符。
  - 04/06 没有 `unsafe { }` 产生式。
  - `extern "C" fun malloc(…)` 在现有语法下推不出来。
- **无语义**：`RawPtr<T>` 的操作集（alloc/free/read/write/offset/cast、`sizeOf/alignOf`）没有，诊断码没有，capability 关系也没有。11 的 Copyable 封闭表和 10 的 Transferable 表都没列 `RawPtr`。按结构推导，`value class Vec(val ptr: RawPtr<T>, …)` 会自动成为 Copyable，double free 就此开门。这是把 Copyable 改成显式 opt-in 的新理由。
- **依赖不存在的机制**：13:265 说靠"RAII"闭合 unsafe 边界，但没有 `deinit`，持有缓冲区的类型无法释放它。所以 `Box/Array/String` 仍只能是编译器魔法，这与该小节"标准库用 Koven 写"矛盾，也与 12:10"容器是编译器预声明原语，不是 .ko API"矛盾。`Vector` 全套规范只在 13 出现一次，12 里叫 `MutableList`。
- **特权模型**：仅限 `koven.*` 命名空间，但 02 规定 package 就是目录路径，所以按名字判定既可伪造，又堵死第三方写 C 库绑定（比如协议栈）。建议改成构建级能力：manifest/driver 开关，所有包可用，配审计 lint，`RawPtr` 放 `core.unsafe`。
- **FFI 类型**：`malloc(size: Int)` 用 32 位有符号 `Int` 对接 `size_t`，64 位目标上 ABI 就错了。需要 `USize` 和 C 类型别名（`CInt/CSize/CPtr`）。

**2. `Box<enum>` 开了口，却没有读取方式。**

- 11:68–70 的 `Expr` 示例要递归，但规范里 Box 只有构造，没有读取、可变访问或拆箱（Rc 反而有 `.value`/`share()`）。加上"不许部分移动"，`eval(e.left)` 写不出来。
- 示例里的 `Num(val value: Int)` 还违反 08 自己的"变体参数不写 `val`"。
- 建议：对称于 Rc 提供 `box.value` 只读/可变投影，再加消费式 `own fun unbox(): T`，并让 `when` 的消费式绑定能穿过 Box。

**3. 15 的 Litmus 有 7/12 被规范自己拒绝。**

| #    | 问题                                                         | 依据                                                         |
| ---- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 4    | `Circle(val radius: Int)`                                    | 08：变体参数不写 `val`                                       |
| 5    | class 体内 `var count: Int = initial`                        | 08：所有 body 拒绝普通 `val`/`var`                           |
| 6    | `identity(value: T): T = value`、`get(): T = item`，从 Borrow 返回 MoveOnly | 10 L0133（08 自己的示例是 `own value: T`）                   |
| 9    | `val fallback: String? = name`（`name` 是 Borrow 参数）      | 10/09 L0133                                                  |
| 10   | `{ y: Int -> … }`                                            | 07：lambda 参数不接受类型；无 expected type 且带参数则 L0083 |
| 11   | `for (i in 1..10)`                                           | 12 §37.1：range 不是 `for` source，L0159                     |
| 12   | `const val READ: Int = 1 shl 0`                              | 05 §36.3：const 子集不含 `shl`，L0156                        |

另外 Litmus 7 能通过，但注释"consume 退出时析构 `r`"与 10 相反：无标记参数是 Borrow，callee 不析构。

修法：把 Litmus 做成 CI 夹具，每块标注 accept 或 reject 加错误码，由真实前端编译。再补负例，尤其是行首 `-`/`+`/`(`/`{`/`!` 不续行，这是新换行规则最容易被误实现的地方。真实程序级验收仍沿用上轮的 12 个，Litmus 只做语法层回归。

## 五、修订后的道路

1. **本周**：清理第四节，Litmus 夹具化，把"取代旧句的 grep"写进升版流程。
2. **阶段 1（语义内核）顺序不变，v0.38 反而把依赖钉得更死**：
   - 借用模型（`Escapable` + 借用返回 + projection）。`.value` 投影、`for` 协议、`Span`/String view、Map 都由它决定。
   - 所有权原语加 `deinit`，它是 unsafe 落地的前置。
   - capability 框架：显式 Copyable、`RawPtr` 的 capability 归属、函数类型限定。
   - 把 13 的 unsafe 小节写成真规则，再把 `Box/Rc/Array/List/String` 迁进库。验收标准是 Koven 能自己写出来。
3. **阶段 2–4 不变**：数值补全（`USize`、wrapping、转换族）、协议与 derive、并发、编译模型。
4. **两个新增的、要早定的决策**：Box 的访问面，以及 unsafe 的特权模型（构建级能力还是命名空间）。
